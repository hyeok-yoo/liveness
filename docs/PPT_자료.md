# PPT 생성용 자료 (AI 입력용)

> **이 문서의 용도**: 발표용 PPT를 AI(예: Gamma, Genspark, Copilot 등)로 생성할 때 그대로 붙여 넣는 입력 자료다.
> 학교 제출용 정식 보고서는 `docs/탐구보고서.md`에 따로 있다. 여기서는 슬라이드별 **핵심 메시지·불릿·시각자료 지시**만 rough하게 담는다. AI가 문장을 다듬고 디자인을 채우는 것을 전제로 한다.

## 0. 발표 메타 정보 (AI에게 주는 전역 지시)

- **주제**: 2D 웹캠만으로 사진·영상 위장 공격을 막는 얼굴 라이브니스 탐지 (rPPG 심박 + 무아레 패턴)
- **발표자**: 고등학교 3학년 2인 팀 프로젝트
- **분량**: 약 12~14 슬라이드, 발표 10~12분 기준
- **구성**: 서론(동기·목적) → 본론(이론·설계·결과) → 결론(결론·느낀점·한계)
- **톤**: 고등학생이 직접 탐구한 프로젝트. 전문적이되 친근하고 자신감 있게. 과장 금지(특히 성능 수치).
- **디자인 가이드**:
  - 컬러: 딥 블루(#4f6bed) + 퍼플 포인트(#8b5cf6), 화이트 배경, 다크 텍스트. 깔끔한 테크 느낌.
  - 슬라이드당 텍스트 최소화 — 큰 키워드 + 도식 위주. 말로 설명할 부분은 발표자 노트로.
  - 도식·아이콘·다이어그램 적극 활용. 수식은 1~2개만 크게.
  - 각 슬라이드 하단에 작은 페이지 번호.
- **반복 강조 메시지(발표 전체의 1줄 핵심)**: *"신호의 세기가 아니라, 얼굴과 배경의 차이를 본다."*

## [서론]

### 슬라이드 1 — 표지
- 제목: **2D 웹캠만으로 "진짜 사람"을 가려낼 수 있을까?**
- 부제: 원격 심박(rPPG) + 무아레 패턴 기반 얼굴 라이브니스 탐지
- 팀명/이름/날짜
- 시각: 얼굴 위에 심박 파형(♥)이 겹쳐진 일러스트, 또는 카메라 아이콘 + 펄스 라인.

### 슬라이드 2 — 탐구 동기 (문제 제기)
- 핵심 멘트: "얼굴로 폰을 여는 게 당연해졌지만, **사진 한 장에 뚫린다면?**"
- 불릿:
  - 깊이/적외선 센서 없는 2D 얼굴 인식은 인쇄 사진·화면 사진·영상 재생에 취약
  - 보급형 기기가 사진 공격에 뚫린 사례 반복 보고
  - 질문: **추가 하드웨어 없이, 평범한 웹캠만으로 사진과 진짜 사람을 구별할 수 있을까?**
- 시각: 폰 앞에 사진을 들이대 잠금이 풀리는 짤막한 그림(Before).

### 슬라이드 3 — 탐구 목적
- 불릿:
  1. 추가 HW 없이 RGB 웹캠만으로 위장 공격 차단 (개념 증명)
  2. 살아있는 사람만의 신호(심박)+화면 재촬영 흔적(무아레)으로 **다층 방어** 설계
  3. 시연 가능 수준 구현 + 정량 지표(FAR/FRR/ACER)로 검증, 한계 규명
- 시각: 목표 3개를 아이콘 카드 3장으로.

## [본론 — 이론적 배경]

### 슬라이드 4 — 위장 공격의 종류
- 표(3행):
  | 공격 | 방법 | 막는 단서 |
  |---|---|---|
  | 인쇄 사진 | 종이 얼굴 | 심박 없음(rPPG) |
  | 화면 사진 | 폰·모니터에 사진 | 심박 없음 + 무아레 |
  | 영상 재생 | 미리 찍은 영상 | 무아레 |
- 멘트: 행동 요구(눈 깜빡임)는 녹화 영상으로 우회 가능 → **위조하기 어려운 물리·생체 신호**에 집중.

### 슬라이드 5 — 핵심 단서 ① rPPG (원격 심박)
- 큰 한 줄: **"사진에는 심장이 없다."**
- 불릿:
  - 심장이 뛰면 피부 혈류가 변해 색이 미세하게 바뀜 (병원 산소포화도 측정 원리)
  - 카메라 영상의 피부색 변화만으로 비접촉 심박 추정 = rPPG
  - 변화량은 RGB의 1% 미만 → 신호처리로 추출
  - 사진엔 이 변화가 없음 → 심박 대역(42~150 BPM)에 신호 없음
- 시각: 피부 확대 + 시간에 따라 미세하게 밝아졌다 어두워지는 파형 애니메이션 느낌.
- (구현 알고리즘: POS, CHROM — 발표자 노트로만)

### 슬라이드 6 — 핵심 단서 ② 무아레 패턴
- 큰 한 줄: **"화면을 다시 찍으면 줄무늬가 생긴다."**
- 불릿:
  - 디스플레이 픽셀 격자 + 카메라 센서 격자 간섭 → 무아레 줄무늬
  - "이 영상은 화면 재촬영물"이라는 강력한 증거
  - 주파수 영역에서 중·고주파 에너지 증가 → 2D FFT로 측정
- 시각: 두 격자가 겹쳐 무아레가 생기는 그림 + 모니터를 폰으로 찍는 사진.

## [본론 — 시스템 설계]

### 슬라이드 7 — 전체 구조: 다층 방어
- 큰 한 줄: **"한 신호가 뚫려도, 다음 층이 막는다."**
- 세로 파이프라인 다이어그램(가장 중요한 도식):
  ```
  카메라(6초) → ①사전검사(조명) → ②얼굴검출/ROI(MediaPipe)
  → ③무아레 FFT → ④무아레 LBP+SVM(선택) → ⑤rPPG 심박 판정
  → ⑥얼굴 인식 → 환영 / 차단 / 미등록
  ```
- 강조: **어느 한 층이라도 의심하면 거부**(보수적 OR 로직). 신원 매칭(⑥)은 라이브니스 통과 후 맨 마지막.
- 시각: 위→아래로 흐르는 파이프, 각 단계에서 사진/영상이 떨어져 나가는(거부) 모습.

### 슬라이드 8 — ⭐핵심 아이디어: 절대값 → 상대값 (가장 강조할 슬라이드)
- 스토리텔링 슬라이드. 좌우 비교 구성 추천.
- **문제(왼쪽)**: 절대 SNR 임계값으로 판정했더니 → *진짜 내 얼굴이 자꾸 거부됨(false reject)*. 조명·카메라·거리마다 신호 세기가 들쭉날쭉.
  - 임계값 ↓ → 사진도 통과(보안 붕괴) / 임계값 ↑ → 본인 거부. 줄다리기 패배.
- **통찰(오른쪽)**: rPPG의 본질은 "세기"가 아니라 **"맥박은 얼굴에만, 배경엔 없다"**.
  - 큰 수식 하나:  **margin = (얼굴 SNR) − (배경 SNR)**
  - 사진: 얼굴 ≈ 배경 → margin ≈ 0 이하
  - 실제 얼굴: 얼굴 ≫ 배경 → margin 큰 양수
  - → 환경이 바뀌어도 차이는 유지 = **강건**
- 발표자 노트: 이게 프로젝트의 전환점. "수식 한 줄이 시스템 전체를 바꿨다."

### 슬라이드 9 — 강건하게 만든 추가 설계
- 불릿(아이콘 카드):
  - **다중 ROI 융합**: 이마+양 볼 신호 가중 합 → 노이즈 상쇄, √N배 보강
  - **다중 윈도우 best-of-N**: 6초를 4초 윈도우로 쪼개 가장 좋은 구간 채택 → 흔들림 무시
  - **best-ROI fallback**: 한 부위만 강해도 통과 → 그림자/가림 대응
  - **신호처리**: Tarvainen 디트렌딩, Hanning+zero-padding FFT, 하모닉 SNR, 포물선 보간
  - **피부 픽셀 마스킹(YCrCb)**: 머리카락·안경 제외 → SNR ↑
- 시각: 핵심 키워드 위주 카드 그리드. 수식 나열 금지.

### 슬라이드 10 — 시연 안전망 & 단순화
- 두 모드:
  - **decisive(기본)**: 사진이면 즉시 거부 — 보안 우선
  - **demo**: rPPG 약하면 경고만, 통과 — *단 사진·영상은 무아레·사전검사가 여전히 차단*
- 단순화 스토리: 처음 10초+모션검사 → **6초로 단축, 모션검사 제거**(rPPG가 이미 흔들림 처리). "방어를 더하는 것만큼 덜어내는 것도 설계."
- 시각: decisive vs demo 토글 스위치 일러스트.

## [본론 — 결과]

### 슬라이드 11 — 데모 (영상/GIF)
- 라이브 데모 또는 녹화:
  - 본인 → "환영합니다" (LIVE 통과)
  - 사진 → "심박 신호 미감지"로 거부 (+화면이면 무아레까지)
- 거부 사유를 **수치 담긴 한국어**로 보여줌: *"심박 신호 미감지 — 얼굴-배경 SNR −2.6 dB < 기준 +1.0 dB"*
- 시각: 웹 제어판 스크린샷 2장(LIVE/SPOOF) 나란히.

### 슬라이드 12 — 평가 결과
- 지표 설명(작게): FAR=위장 통과율(↓ 안전), FRR=본인 거부율(↓ 편의), ACER=평균
- 결과 표(개념 증명 수준 강조):
  | 케이스 | margin | 판정 |
  |---|---|---|
  | 실제 얼굴 | +3 ~ +15 dB | LIVE ✓ |
  | 사진 | −1.2 ~ −4.2 dB | SPOOF ✓ |
- ablation: 무아레만 / rPPG만 / 전체 → 각 층 기여도 비교 설계
- ⚠️ 정직 표기: **소규모 2인 데이터 기반 개념 증명** — 통계 일반화엔 한계.
- 시각: margin 분포를 점/막대로 (live는 양수쪽, spoof는 0 이하쪽).

## [결론]

### 슬라이드 13 — 결론
- 두 줄 요약:
  1. **다층 방어**로 사진(rPPG)·영상(무아레)을 서로 다른 단서가 차단 — 단일 실패 지점 제거
  2. **배경 상대 margin**으로 환경에 강건한 판정 — 절대값→상대값 관점 전환이 핵심
- 한 줄: "false reject ↔ false accept의 균형은, 임계값 조절이 아니라 *판정 관점의 전환*으로 풀었다."

### 슬라이드 14 — 느낀점 · 한계 · 향후
- **느낀점**: 막히면 원리로 돌아가라(수식 한 줄이 시스템을 바꿈) / 사용성도 설계다 / 보안의 trade-off를 몸으로 배움
- **한계(정직하게)**:
  - 고화질 OLED 원본 영상 재생은 막기 어려움(가장 근본적 한계)
  - 무아레 임계값 환경 민감 / 소규모 데이터 / 수 초 캡처 필요 / 측면·저조도 취약
- **향후**: 무아레 LBP+SVM 학습, OLED 재생 대응 단서, 모바일·브라우저 이식, 표본 확대
- 시각: 좌(배운 점)·중(한계)·우(다음 단계) 3열.

## 부록 A — 예상 질문 & 답변 (발표자 노트용, 슬라이드에는 넣지 말 것)

- **Q. 사진을 천천히 흔들면 심박처럼 보이지 않나요?**
  A. 흔들면 얼굴·배경이 같이 움직여 같은 주파수가 생겨 margin이 안 생깁니다. 게다가 큰 움직임은 rPPG 다중 윈도우가 회피하거나 얼굴 검출 프레임 부족으로 먼저 걸립니다.
- **Q. 왜 딥러닝(CNN)을 안 썼나요?**
  A. 2인·소규모 데이터(클래스당 ~10장)라 과적합 위험이 큽니다. rPPG는 물리 원리 기반 룰이라 학습 데이터가 필요 없고, 거부 이유를 수치로 설명할 수 있습니다. (무아레는 향후 학습형 보강 설계.)
- **Q. 고화질 화면으로 영상을 재생하면요?**
  A. 무아레가 약해질 수 있어 단독 의존하지 않습니다. rPPG·사전검사가 함께 막습니다. 다만 OLED 원본 영상 재생은 근본적 한계로 정직하게 밝힙니다.
- **Q. 본인인데 거부되면?**
  A. 초기 핵심 문제였고, 상대 margin 전환+신호처리 강화로 해결했습니다. 발표장처럼 환경이 미지수일 땐 demo 모드로 rPPG 거부권을 빼되 사진·영상 차단은 유지합니다.
- **Q. ROI를 왜 이마·양 볼 3곳으로?**
  A. 혈류가 풍부하고 간섭이 적은 부위입니다. 여러 부위를 융합하면 신호가 강해지고, 부위별 심박수 일치로 가짜 신호를 한 번 더 검증합니다.
